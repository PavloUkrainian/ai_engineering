# AI Engineering: Кейс 1 — Вилучення структурованих даних з документів (DocAI / KYC)

Цей репозиторій містить рішення Кейсу 1 наскрізного проєкту курсу **AI Engineering (2 потік)**.

## 🎯 Предметна область (Домен)
**Оптичне розпізнавання та вилучення даних з документів, що посвідчують особу (DocAI / Identity Verification / KYC)**.

У реальних системах мобільні сканери та OCR-рушії генерують сильно зашумлений текст:
- Оптичні артефакти (заміна `O` на `0`, `l` на `1`, шум `###`, відблиски на голограмах);
- Розірвані рядки, обрізані краї карток;
- Розріджений текст із пробілами між літерами (`К Р А В Ч У К`);
- Багатомовність (українська кирилиця + латинська транслітерація);
- Машинозчитувані зони (MRZ-стрічки) різного ступеня цілісності.

Завдання сервісу — перетворити цей «сирий» текст на валідний, суворо валідований Pydantic-об'єкт `ExtractedDocument` для автоматизованої верифікації без участі людини.

## 🚀 Швидкий запуск (One-command run)

### 1. Системні вимоги та режими роботи
- **Python 3.11+** (перевірено на Python 3.12).
- **Production Benchmark Mode (Реальний бенчмарк — за замовчуванням):**
  - Потребує налаштованого `OPENAI_API_KEY` у `.env` для `gpt-4o-mini` та запущеного екземпляра Ollama (`ollama run llama3.2`) для локальної моделі.
  - Параметр `USE_MOCK_FALLBACK=false` встановлено за замовчуванням. Усі 180 записів у каталозі `results/` отримані виключно в цьому режимі (`is_mock=false`).
- **Offline Smoke-Test Mode (Режим тестування коду пайплайну):**
  - Якщо ключ API або Ollama відсутні, можна явно передати `USE_MOCK_FALLBACK=true` у `.env` виключно для перевірки проходження коду пайплайну та схеми валідації без звернення до мережі (такі записи маркуються `is_mock=true`).
  - ⚠️ **Дисклеймер:** Емуляція (Mock Fallback) призначена лише для швидкої перевірки працездатності коду та unit-тестів; вона **не замінює** і не може замінювати чесні емпіричні виміри якості моделей.

### 2. Запуск однією командою
`Makefile` та `run.sh` налаштовані як **повністю самодостатні (Self-Bootstrapping)**. Вони автоматично створять віртуальне середовище `.venv` та встановлять необхідні пакети з `requirements.txt`, якщо вони ще не встановлені:

```bash
# Повний запуск повної сітки експериментів:
make run
# або
./run.sh
```

### 3. Запуск окремого Кроку 1 (Baseline):
```bash
make step1
# або
./run.sh --step 1
```

### 4. Запуск автоматизованих тестів:
```bash
make test
# або
./.venv/bin/python -m unittest discover tests
```
